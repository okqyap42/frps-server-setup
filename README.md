## 按使用场景判断 frps 需要什么配置

先想清楚你要往外映射什么，配置需求基本就定了。frps 只做流量转发，不跑业务逻辑，所以规格压力远小于同等访问量的应用服务器，瓶颈几乎总在带宽和端口上。

## frp 到底解决什么问题，为什么必须要一台公网服务器

frp 是开源的反向代理工具，支持 TCP、UDP、HTTP、HTTPS，也支持 P2P 通信，项目在 GitHub 上持续维护。它的工作方式很直接：有公网 IP 的服务器上跑服务端 frps，没有公网 IP 的内网机器上跑客户端 frpc，**frpc 主动向 frps 建立连接**，外部访问云服务器的某个端口，流量就被转发到内网的真实服务上。

关键点在“frpc 主动连出去”。内网那台机器不需要公网 IP、不需要改路由器、不需要端口映射，只要是能上网的环境就行。需要公网 IP 的只有 frps 所在的这一台。

典型用法：在外面访问家里的 NAS 管理页；把公司内网开发机的 SSH 暴露出来；把本地正在调的服务临时给协作方看；远程连家里 Windows 主机的 3389 桌面；把内网的 Jenkins 发布到公网触发构建。

frp 支持的代理类型不止 TCP。HTTP/HTTPS 类型可以按域名路由，STCP/SUDP 要求访问端也装 frpc、不在服务端暴露端口，XTCP 走点对点、流量不经服务器中转，TCPMUX 能让同一个端口复用访问不同内网服务。刚上手只用 TCP 就够，其余等有具体需求再看。

## 第一步：确认你手上这个版本该写 TOML 还是 INI

这是最容易浪费时间的一步。两种格式不能混用，报错信息也不会告诉你“你抄了旧教程”。

判断方法有两个，都不用猜：

1. 解压下载的压缩包，看目录里自带的示例配置文件叫什么。叫 `frps.toml` / `frpc.toml` 就是新格式，叫 `frps.ini` / `frpc.ini` 就是旧格式。
2. 打开 frp 官方文档，看当前版本文档里的配置示例用的是哪种语法。以官方文档为准，不以教程文章的发布日期为准。

程序包统一从 GitHub Releases 取，选对应操作系统和架构的压缩包。版本号会持续更新，直接下载当前发布的最新一个即可，不要记某个具体版本号去找。

两种格式的差异不止是文件名：

- 旧格式有 `[common]` 段落，新格式没有段落，全部平铺；
- 键名从下划线改成驼峰，`bind_port` 变成 `bindPort`，`dashboard_port` 变成 `webServer.port`；
- 嵌套结构用点号表示，`auth.token`、`log.level`、`webServer.user`。

网上那些 `privilege_mode`、`authentication_timeout`、`max_pool_count` 之类的字段属于旧版本，新配置文件里写了不会生效，甚至直接报错。

## 第二步：服务端最小可用配置

在云服务器上建一个 `frps.toml`，先只写两行：

toml
bindPort = 7000
auth.token = "换成一串足够长的随机字符"


`bindPort` 是 frpc 连接 frps 用的端口，两端必须一致。`auth.token` 是两端共享的密钥，frpc 必须填完全相同的值才能连上，这是防止别人蹭你中转的基本防护。

启动：

bash
./frps -c frps.toml


看到启动日志没报错，服务端就算跑起来了。`7000` 只是示例值，不是强制值，改成 8000、9527、10001 都行，只要 frpc 配置和防火墙放通的是同一个数字。

## 第三步：需要后台面板和日志就补上这些

只有两行的配置跑得起来，但出问题没有日志可看。加几行常用的：

toml
bindAddr = "0.0.0.0"
bindPort = 7000

webServer.addr = "0.0.0.0"
webServer.port = 7500
webServer.user = "你自己的用户名"
webServer.password = "一个强密码"

auth.method = "token"
auth.token = "换成一串足够长的随机字符"

log.to = "/var/log/frps.log"
log.level = "info"
log.maxDays = 3


设了 `webServer.port` 才会有 dashboard 页面，浏览器打开 `服务器IP:7500` 能看到当前连接和代理状态。`7500` 同样是惯例值，可以换。

这里有个几乎所有教程都在犯的错：示例里清一色写 `admin/admin`、`token = "123456"`。这些是文档占位符，原样照抄等于给公网开了一扇没锁的门，扫描器几分钟就能撞上。用户名密码和 token 都自己生成，token 用 32 位以上随机串。

## 第四步：配成 systemd 服务，别用 nohup 裸跑

用 `nohup ./frps &` 挂着的进程，服务器一重启就没了，断了也不会自动拉起。正式使用建议写成 systemd 单元：

ini
[Unit]
Description = frp server
After = network.target syslog.target
Wants = network.target

[Service]
Type = simple
ExecStart = /app/frp/frps -c /app/frp/frps.toml

[Install]
WantedBy = multi-user.target


保存为 `/etc/systemd/system/frps.service`，路径按你实际放程序的位置改，必须写绝对路径。然后：

bash
systemctl daemon-reload
systemctl start frps
systemctl enable frps


`enable` 这一步别忘，否则开机还是不会自启。

## 第五步：放通端口，这里分两类

端口放通是内网穿透连不通最常见的原因，而且要在两个地方都做：云服务器系统内部的防火墙（firewalld、ufw），以及云厂商控制台上的安全组或防火墙规则。各家叫法不同，腾讯云轻量应用服务器叫“防火墙”，阿里云 ECS 叫“安全组”，本质是同一层。

要放通的是两类端口：

- **`bindPort`**，示例 7000，供 frpc 连接 frps，不放通客户端直接连不上；
- **`remotePort`**，也就是你在 frpc 里配置的、映射到云服务器上的对外端口，不放通外部访问不到服务。

有人遇到过开放 7000 端口后客户端仍然连接超时、换成别的端口就恢复正常的情况，这是个别环境下的经历，不是通用结论。真遇到连不上，可以先换一个端口试，但优先排查的还是 token 和防火墙规则本身。

## 第六步：客户端配置要和服务端对上

内网机器上建 `frpc.toml`。假设要把本地 80 端口的 Web 服务映射到云服务器的 8080：

toml
serverAddr = "云服务器公网IP"
serverPort = 7000
auth.token = "与服务端完全相同的密钥"

[[proxies]]
name = "web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 80
remotePort = 8080


`serverAddr`/`serverPort` 指向 frps，`localPort` 是内网服务真实监听的端口，`remotePort` 是对外暴露的端口。改完启动 `./frpc -c frpc.toml`。

## 怎么确认搭成功了？按这个顺序查

三项验证，全过就是链路通了：

1. 云服务器上 frps 进程在跑，日志没有报错；
2. 内网机器上 frpc 启动后，日志里有成功连接 frps 的提示（类似 `start proxy success`）；
3. 用浏览器或命令行访问 `云服务器IP:remotePort`，能看到内网服务的真实内容。

不通的时候别一个个现象试，按固定顺序排查最快：

**先查 token** → 两端是不是完全一致，多一个空格、少一个字符都连不上。
**再查端口** → `bindPort` 在云厂商控制台和系统防火墙里都放通了吗。
**最后查连通** → frpc 日志里到底有没有连上 frps，没连上就翻 frps 的日志看有没有拒绝记录。

如果是“连上了但访问不到服务”，方向换成另外两个：`remotePort` 放通了没有；内网服务是不是真的跑在 `localPort` 上（在本地 `curl 127.0.0.1:80` 试一下就知道）。

## 三个照抄就会出事的安全项

穿透的本质是把内网服务搬到公网上，暴露出去的端口会被全网扫。三件事必须做：

**换掉所有示例弱口令。** dashboard 的 `admin/admin`、`token = "123456"`，这两个组合在教程里出现频率极高，也是扫描字典里的头几条。

**内网 SSH 改密钥登录、关掉密码登录。** 把 22 端口映射出去又不改认证方式，等于把爆破入口直接摆到公网，挖矿木马就是这么进来的。

**映射端口限制来源 IP。** 如果只在自己公司和家访问，就在安全组里把 `remotePort` 的入站规则限制成固定 IP，比开放 0.0.0.0/0 安全得多。管理类页面（路由器后台、NAS 管理页、数据库端口）尤其不要对全网开放。

另外，只暴露你自己拥有、用途合规的内网服务。绕过网络管理规定或者暴露未授权系统，出问题的是你。

## 几个教程很少写、但实际会用到的配置

**用 `includes` 拆分配置文件。** 一台 frpc 要管五六个内网服务时，全塞在一个文件里很快就乱了。客户端配置写 `includes = ["./conf.d/*.toml"]`，每个服务单独一个文件（比如 `jenkins.toml` 里写 name、type、localIP、localPort、remotePort），增删服务只动一个几十行的文件。

**用 `allowPorts` 限制客户端可占的端口。** 多人共用一台 frps 时，`allowPorts = [{ start = 2000, end = 3000 }, { single = 3001 }]` 能把客户端可绑定的端口限定在列表内，默认是不限制。配合 `maxPortsPerClient`（0 为不限）还能限制每个客户端的端口数量，防止端口被一个人占满。

**`remotePort = 0` 让 frps 随机分配端口。** 不在乎对外端口号是多少、只想拿到一个可用端口时很方便，省去手工挑空端口的麻烦。

**`healthCheck` 做后端健康检查。** 支持 tcp 和 http 两种，配 `healthCheck.type`、`timeoutSeconds`、`maxFailed`、`intervalSeconds`，内网服务挂了之后 frps 会把该代理摘掉，不会持续往死链路上转发。

**要域名加 HTTPS，用 Caddy 反代。** 在云服务器上装 Caddy，反代到 frps 映射出的端口，证书由 Caddy 自动申请续期，比在 frp 里折腾 `vhostHTTPSPort` 简单。frps 自身也支持 `vhostHTTPPort`/`vhostHTTPSPort` 加 `subDomainHost` 做域名路由，但需要客户端配合 `subdomain` 或 `customDomains`，配置量更大。

这些字段的默认值和可选项随版本变化，动之前翻一眼官方文档对应版本的说明。

## 常见问题

**frpc 一直连不上 frps，日志显示连接超时？**
按上面三步顺序查：token 是否完全一致、`bindPort` 是否在云厂商控制台和系统防火墙两处都放通、用 `telnet 服务器IP 7000` 能不能通。三处都排除后，再考虑换端口试。

**日志显示连上了，但外网打不开服务？**
先确认 `remotePort` 放通了，再用 `curl 127.0.0.1:本地端口` 确认内网服务本身在正常响应。两处都正常，检查 frpc 配置里的 `localIP` 是不是写错了（容器里跑的服务可能是 `172.17.0.1` 而不是 `127.0.0.1`）。

**frps 要不要配 HTTPS 证书？**
frpc 和 frps 之间的通信从 v0.50.0 起默认启用 TLS（`transport.tls.enable` 默认 true），不需要你手动配证书。对外访问的 HTTPS 是另一回事，走 Caddy 反代更省事。

**必须装宝塔吗？**
不必须。命令行加 systemd 是标准做法，占用小、可控性强。宝塔的价值在于用图形界面管理进程和文件，适合不熟悉 Linux 的人。两套方案选一套，别混着来。

**年付更划算吗？续费会涨价吗？**
这取决于具体服务商的计费规则，各家不同。下单前看清三件事：年付折扣是不是循环折扣（续费同价，还是只有首期优惠）、续费价与首期价的差额、退款政策覆盖哪些情况。雨云的长期支付折扣和退款条款在官方页面有明确说明，别只看首月价格做决定。
